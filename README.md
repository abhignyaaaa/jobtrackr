# JobTrackr — Cloud Job & Internship Application Tracker

A cloud-hosted web app for students to track internship, campus-placement and
off-campus applications: statuses with full history, deadlines, interviews,
private resume storage, and a dashboard computed from real database records.

**Stack:** Python 3.13 · FastAPI · SQLAlchemy 2 · PostgreSQL · Jinja2 (server-rendered) ·
Chart.js (self-hosted) · Argon2id · Render (PaaS) · optional S3-compatible object storage

---

## 1. Features

| Module | What's implemented |
|---|---|
| Authentication | Register, login, logout, change password (signs out other devices), time-zone setting. Argon2id hashes, server-side sessions, CSRF protection, login rate limiting, generic error messages. |
| Applications | Create / view / edit / delete; company, title, description, URL, location, employment type, source, applied date, deadline, compensation range (currency + period), status, notes. Search, filter (status, type, company, date range), sort, paginate (10/page), CSV export. |
| Status tracking | Saved → Applied → Assessment → Interview → Offer Received / Rejected / Withdrawn. Every change is recorded in `status_changes` with timestamp and optional note. Applied date auto-fills when an application leaves "Saved". |
| Interviews | Date/time (stored UTC, shown in user's zone), round, type, mode, meeting link, prep notes, result. Adding an interview advances the status to Interview. Upcoming / past views. |
| Reminders (in-app) | Dashboard panel of interviews and deadlines in the next 14 days, recently missed deadlines, and a nav badge for anything due within 48 hours. |
| Dashboard | Total, applied this month, awaiting response, upcoming interviews, offers, rejected; status-distribution and weekly-activity charts; interview and offer conversion with stated denominators. All queried live from Postgres. |
| Documents | PDF/DOC/DOCX upload (5 MB, 20 per user), magic-byte validation, opaque storage keys, owner-only download via 60-second pre-signed URLs. Behind `STORAGE_BACKEND` switch. |

### Metric definitions (also shown on the dashboard)
- **Submitted** (denominator for conversion): applications whose status history contains any status other than *Saved*.
- **Interview rate** = submitted applications that were ever marked *Interview* or have ≥1 interview recorded ÷ submitted.
- **Offer rate** = submitted applications ever marked *Offer Received* ÷ submitted.
- **Awaiting response** = current status *Applied*. **Applied this month** = applied date in the current calendar month (user's time zone).
- With zero submitted applications the rates show "—", never a made-up percentage.

## 2. Cloud architecture

```
 Browser (laptop / phone)
        │  HTTPS (TLS terminated by Render, auto-renewed certificate)
        ▼
 ┌─────────────────────────── Render (Singapore region) ───────────────────────────┐
 │  Render load balancer / proxy  ──►  Web Service "jobtrackr" (free instance)       │
 │                                     uvicorn × 2 workers · FastAPI app             │
 │                                     /healthz health check                          │
 │                                            │ private network (no public route)     │
 │                                            ▼                                       │
 │                                     Render PostgreSQL "jobtrackr-db"               │
 │                                     ipAllowList: []  (external access blocked)     │
 └──────────────────────────────────────────────────────────────────────────────────┘
        │ (optional) HTTPS, SigV4-signed
        ▼
 S3-compatible private bucket (resumes) — downloads via 60 s pre-signed URLs
```

- **Model:** PaaS. Render builds from GitHub on every push (`autoDeploy`), runs the
  container, provides TLS, health checks and zero-config HTTPS.
- **Infrastructure as code:** `render.yaml` declares the web service, the database,
  environment variables and the link between them.
- **Configuration:** 12-factor; all settings come from environment variables
  (`app/config.py`). `SECRET_KEY` is generated by Render; `DATABASE_URL` is injected
  from the database resource. No secrets in the repository.

## 3. Networking

- Public entry point is only the HTTPS URL `https://<service>.onrender.com`; HTTP
  redirects to HTTPS and the app sends HSTS.
- The app reaches Postgres over Render's **private network** (`connectionString`
  is the internal URL). `ipAllowList: []` blocks every external connection to the DB.
- Uvicorn runs with `--proxy-headers` so the real client IP (from Render's proxy) is
  used for login rate limiting.
- The browser loads nothing from third-party CDNs: Chart.js is self-hosted, so the
  Content-Security-Policy can be `script-src 'self'`.

## 4. Security

| Threat | Control |
|---|---|
| Password theft from DB | Argon2id (memory-hard); plaintext never stored or logged. |
| Session theft | Random 256-bit token in `HttpOnly`, `Secure`, `SameSite=Lax` cookie; only its SHA-256 is stored. 7-day absolute + 48-hour idle expiry. Logout and password change revoke sessions server-side. New session on every login (no fixation). |
| CSRF | Per-session synchronizer token on every form; double-submit token for anonymous forms; Origin header check. |
| Brute force | 5 failures per email+IP or 30 per IP in 15 minutes → HTTP 429. |
| User enumeration | Identical "Incorrect email or password" response; dummy hash verify equalises timing. |
| IDOR (reading another user's data) | Every query is scoped by `user_id`; foreign IDs return 404 (not 403) so existence isn't leaked. Covered by tests. |
| XSS | Jinja2 auto-escaping; strict CSP (no inline script/style); URLs restricted to http(s); links use `rel="noopener noreferrer"`. |
| SQL injection | SQLAlchemy parameterised queries; sort columns from a whitelist; LIKE wildcards escaped. |
| Open redirect | `next` parameter accepted only for local paths. |
| Clickjacking / sniffing | `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`. |
| Malicious uploads | Extension whitelist + magic-byte check, size cap enforced before and after parsing, server-generated keys, `Content-Disposition: attachment`, private bucket. |
| CSV/formula injection | Cells starting with `= + - @` are prefixed with `'` in exports. |
| Info leakage | No stack traces to users; OpenAPI docs disabled; private pages sent `Cache-Control: no-store`. |

## 5. Scalability

- **Stateless web tier:** sessions live in Postgres, not memory, so any number of
  instances can serve any request. Scaling out is a plan change on Render
  (`numInstances` / autoscaling on paid plans).
- **Database:** indexes on `user_id`, `(user_id, status)`, `(user_id, applied_on)`,
  `scheduled_at`; metrics use `COUNT`/`EXISTS` aggregate queries instead of loading
  rows; connection pooling with `pool_pre_ping`. Next steps at scale: Render's
  connection pooler, read replica for dashboards, Alembic migrations.
- **Pagination** keeps list pages O(page size).
- **Object storage** keeps large files out of the database and the app servers.
- **Free-tier limits** (honest): one instance, sleeps after 15 min idle (~1 min cold
  start), free Postgres is 1 GB and expires 30 days after creation.

## 6. Cost analysis (USD; check current pricing before relying on it)

| Scenario | Web service | Database | Storage | Monthly |
|---|---|---|---|---|
| Demo / coursework | Render Free | Render Free (30-day expiry) or Neon Free | disabled or a free S3-compatible tier | **$0** |
| Small real use (always-on) | Render Starter | Render Basic Postgres | S3-compatible, a few GB | low tens of dollars |
| Growth | Standard + autoscaling | larger Postgres + read replica | S3 + CDN | scales with traffic |

Cost drivers: instance hours (750 free/month), Postgres size/plan, outbound bandwidth,
and object storage GB + requests. The app is lightweight (2 workers fit in 512 MB).

## 7. Testing

`pytest` runs **28 tests against a real PostgreSQL database**, including:
auth flows, hashing, session revocation, rate limiting, CSRF (missing, forged,
cross-origin), open-redirect blocking, security headers, cross-user isolation
(read/edit/delete/status/interview/document/CSV), XSS escaping, validation, search with
LIKE-wildcard escaping, filters/sort/pagination, CSV formula neutralisation,
interview time-zone handling, metric correctness against hand-computed values,
reminders, upload validation (type spoofing, size, empty) and the S3 backend (moto).

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
createdb jobtracker_test   # PostgreSQL user/password per tests/conftest.py
pytest -q
```

## 8. Run locally

```bash
cp .env.example .env        # then export the variables, or set them in your shell
python -m app.init_db
uvicorn app.main:app --reload
```

Demo data (goes through the real HTTP endpoints, so all numbers are genuine):

```bash
python scripts/seed_demo.py --base-url http://localhost:8000 --email demo@example.com --password 'DemoPass123'
```

## 9. Deploy to Render

1. Push this repository to GitHub.
2. Render Dashboard → **New → Blueprint** → select the repo → **Apply**.
   Render creates `jobtrackr-db` and `jobtrackr`, wires `DATABASE_URL`, generates `SECRET_KEY`.
3. Open `https://<service>.onrender.com/healthz` → `{"status":"ok","database":"ok"}`.

To enable resume uploads, set `STORAGE_BACKEND=s3` and `S3_BUCKET`, `S3_ENDPOINT_URL`,
`S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (keep the bucket private).
